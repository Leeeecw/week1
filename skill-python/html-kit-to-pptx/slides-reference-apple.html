PPTX 환산: 1280 × 720px = 13.333 × 7.5in (96 DPI). px 값을 96으로 나누면 인치, 혹은 ×9525 하면 EMU입니다. 좌우 여백 88px ≈ 0.917in, 상하 64px ≈ 0.667in.

01

타이틀 / 표지

화이트 캔버스 + 좌측 정렬 히어로. 웹 스펙의 중앙 정렬 히어로를 슬라이드에서는 좌측 정렬로 바꿨습니다 — 제목이 길어져도 무게중심이 흔들리지 않고, 발표자/날짜 메타를 아래쪽에 안정적으로 붙일 수 있습니다. 제목은 60px / 600 / 자간 −1.4px, 부제는 26px / 400. 표지에는 러너(페이지 번호)를 넣지 않습니다.

03

섹션 구분 (다크 타일)

이 시스템에서 구분선은 면의 색 변화 그 자체입니다. 챕터가 바뀔 때 라이트 → 다크로 넘기면 별도의 장식 없이 리듬이 생깁니다. 다크 면에서 링크·액센트는 #2997ff(Sky Link Blue)로 바꿉니다 — #0066cc는 어두운 배경에서 묻힙니다. 큰 숫자 + 제목 + 한 줄 요약, 그 이상은 넣지 않습니다.

04

기본 본문 — 제목 + 리드 + 불릿

가장 많이 쓸 형태. 제목 44px → 액센트 룰 → 리드 26px → 불릿 20px의 수직 리듬이 고정입니다. 불릿은 최대 5개, 한 항목 2줄 이내. 불릿 점은 7px 원형 액센트로, 텍스트 첫 줄 중앙(top:11px)에 정렬됩니다. 본문 폭은 860px 이하로 제한 — 1280px를 꽉 채우면 한 줄이 너무 길어 읽는 속도가 떨어집니다.

Principles

UI는 물러나고 콘텐츠가 말한다

장식적인 요소를 제거할수록 콘텐츠의 존재감이 커집니다. 이 시스템이 금지하는 것들의 목록은 허용하는 것들의 목록보다 깁니다.

  • 섹션 구분에 선이나 박스를 쓰지 않습니다. 면의 색이 바뀌는 것이 구분입니다.
  • 액센트 컬러는 하나뿐입니다. 두 번째 브랜드 컬러를 도입하는 순간 "클릭 가능"이라는 신호가 희석됩니다.
  • 그림자는 이미지가 표면 위에 놓였다는 물리적 사실을 표현할 때만 씁니다. 카드·버튼·텍스트에는 없습니다.
  • 그라디언트는 쓰지 않습니다. 분위기는 사진이 만들고, CSS는 만들지 않습니다.
  • 강조가 필요하면 먼저 면을 바꾸세요. 테두리나 색을 더하는 것은 그다음입니다.
01 · 설계 원칙04
05

2단 분할 — 설명 + 비주얼

좌측 텍스트 : 우측 이미지 = 1.15 : 1, 간격 48px. 이미지 자리에는 시스템의 유일한 그림자(rgba(0,0,0,.22) 3px 5px 30px)가 붙습니다. 좌우를 바꿔도 되지만 한 덱 안에서는 방향을 일관되게 유지하세요. 이미지 캡션은 15px, ink-muted-48.

Elevation

그림자는 하나면 충분하다

이 시스템에는 그림자 토큰이 단 하나 있습니다. 그리고 그것은 UI 계층을 만들기 위한 것이 아니라, 이미지가 표면 위에 실제로 놓여 있다는 무게감을 주기 위한 것입니다.

카드가 떠 보여야 한다면 그림자 대신 1px 헤어라인을, 바가 떠 있어야 한다면 backdrop-blur를 씁니다.

05 · 깊이와 그림자05
06

3열 카드 그리드

카드는 흰 배경 + 1px #e0e0e0 헤어라인 + radius 18px + 패딩 24px. 그림자는 없습니다. 카드 안 썸네일은 radius 8px(내부 이미지 문법). 3열이 기본이고, 항목이 4개면 4열, 6개면 3열×2행으로 갑니다. 5열 이상은 슬라이드에서 글자가 작아져 권장하지 않습니다.

수치 강조 (KPI 행)

숫자는 56px / 600 / 자간 −1.6px에 액센트 컬러를 씁니다. 이 시스템에서 색으로 강조하는 것은 인터랙티브 요소가 원칙이지만, 수치는 "읽는 사람이 가져가야 할 한 가지"라는 점에서 예외를 둡니다. 한 슬라이드에 3~4개까지. 항목 사이는 세로 헤어라인 대신 여백으로 구분합니다.

08

표 — 가로 헤어라인만

세로 괘선, 줄무늬 배경, 셀 테두리를 쓰지 않습니다. 헤더는 15px 대문자 + ink-muted-48 + 하단 1px 잉크 라인, 각 행은 하단 1px #e0e0e0. 숫자 열은 우측 정렬 + tabular-nums. 행 높이는 상하 18px 패딩으로 약 55px — 슬라이드에서는 7행 이내가 읽기 한계입니다.

03 · 타이포그래피08
09

단계 / 프로세스 (4스텝)

화살표 도형 대신 번호 배지 + 상단 헤어라인으로 순서를 표현합니다. 배지는 32px 원형 액센트. 각 스텝의 상단 라인이 시각적으로 이어지면서 진행 방향을 암시합니다. 스텝이 5개를 넘으면 가로 배열 대신 좌측 번호 목록(2열)으로 바꾸세요.

Workflow

적용 순서

1

토큰 고정

색·타이포·간격을 먼저 확정합니다. 이후 단계에서 하드코딩된 값을 쓰지 않습니다.

2

면 리듬 설계

라이트 → 다크 → 라이트의 순서를 먼저 짭니다. 내용은 그 위에 얹습니다.

3

컴포넌트 배치

버튼은 두 문법(pill·유틸)만, 카드는 한 문법만 씁니다.

4

여백 검수

이미지 주변 40px, 제목 위 64px이 확보됐는지 마지막에 확인합니다.

진행 중인 단계는 상단 라인과 배지를 액센트로, 남은 단계는 헤어라인과 회색 배지로 표시합니다.

10

인용 / 한 문장 메시지 (다크)

따옴표 이미지나 인용 박스를 쓰지 않습니다. 어두운 면 + 넓은 여백 + 큰 활자만으로 인용임이 드러납니다. 문장은 40~44px / 400(굵게 하지 않음), 최대 3줄. 출처는 15px로 액센트 룰 뒤에 둡니다. 발표 중 잠시 멈추는 자리에 배치하세요.

벽이 사라지면 작품이 드러납니다. 좋은 인터페이스는 자신을 설명하지 않고, 무엇을 보아야 하는지만 알려줍니다.

대비 / 비교 — 풀블리드 2분할

비교는 카드 두 장이 아니라 화면을 좌우로 갈라 면 색을 다르게 해서 표현합니다. 이것이 이 시스템에서 "구분선 없이 구분하기"의 가장 직접적인 사례입니다. 각 면의 내부 패딩은 슬라이드 여백과 동일한 88 / 64px를 유지해 두 면의 텍스트 기준선이 맞습니다.

Don't

장식으로 위계 만들기

  • 카드마다 그림자를 더해 떠 보이게 한다
  • 구역마다 테두리와 배경 그라디언트를 넣는다
  • 강조할 때마다 새로운 색을 하나씩 추가한다

요소가 늘수록 무엇이 중요한지 알기 어려워집니다.

Do

면 전환으로 위계 만들기

  • 배경색을 바꿔 섹션을 나눈다
  • 여백을 늘려 중요한 것 주변을 비운다
  • 액센트는 하나로 두고 위치로 강조한다

더할 것을 고민하기 전에 뺄 것을 먼저 찾습니다.

체크리스트 (Do / Don't)

초록/빨강 아이콘을 쓰지 않습니다 — 두 번째 색을 도입하는 순간 단일 액센트 원칙이 깨집니다. 대신 Do는 액센트 색 라벨 + 채워진 점, Don't는 회색 라벨 + 빈 원으로 구분합니다. 좌우 2열, 각 4~5항목. 항목당 한 줄을 넘지 않게 씁니다.

Guidelines

지켜야 할 것과 피해야 할 것

Do

  • 본문은 한 덱 전체에서 20px / 400 하나로 통일
  • 제목에 음수 자간(−0.8 ~ −1.4px)을 반드시 적용
  • 섹션 전환은 배경색 변경으로 처리
  • 액션은 pill, 유틸리티는 radius 8px 사각
  • 이미지 주변 최소 40px 확보

Don't

PPTX 변환 기준값

GEOMETRY

슬라이드1280 × 720px = 13.333 × 7.5in
좌우 여백88px = 0.917in
상하 여백64px = 0.667in
본문 최대 폭860 ~ 900px
러너 높이56px = 0.583in

CONVERSION

  • px → inch = px ÷ 96 · px → EMU = px × 9525
  • px → pt = px × 0.75 (제목 44px ≈ 33pt, 본문 20px = 15pt)
  • 자간은 PPTX에서 pt 단위 — −1.0px ≈ −0.75pt
  • Arial은 Windows·macOS·Office 공통 내장이라 치환 위험이 없습니다
  • 그림자는 제품 이미지 도형에만: blur 30px, offset 3/5px, 22% 검정

PPTX에는 CSS flex가 없으므로, 각 슬라이드를 옮길 때는 위 여백 기준으로 절대 좌표를 계산해 배치하세요. 제목 블록은 좌측 88px / 상단 64px에서 시작하고, 러너는 하단에서 56px 높이로 고정됩니다.
